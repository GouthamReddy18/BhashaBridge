# Dataset splits

No train, validation, or test split is created for the current data. Never use unreviewed drafts as held-out evaluation data. For a future reviewed release, assign `train`, `validation`, or `test` in the annotation record and provide a stable `split_group`. Group exact/near-duplicate sentences, paraphrases, related sources, shared templates, generated variants, and repeated ambiguity contexts before assigning groups deterministically. Freeze and version the assignment mapping and seed; do not split a group across partitions. Track review status independently from split membership and inspect source/template overlap for leakage. The readiness checker detects group conflicts and exact duplicate normalized text across splits; it does not detect paraphrases, templates, or semantic near-duplicates. No evaluation scores are reported. See [the evaluation protocol](../../docs/evaluation_protocol.md).
