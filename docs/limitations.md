# Limitations and integrity statement

Phase 2B adds a conservative token-level language-identification baseline. Deterministic labels are based on token type, Unicode number category, Telugu Unicode block, and small exact-match English/Romanized Telugu seed lists. These are transparent heuristics, not a trained baseline with measured accuracy. Telugu-block detection reports script, not guaranteed language identity. Tokens without evidence remain `UNKNOWN`; no confidence is emitted for rules.

IndicLID is optional and disabled by default. Local FastText branches can be configured, but the upstream project describes sentence-level identification. Running one token at a time is an unvalidated adaptation, especially for short Romanized words and code-mixed input. Returned FastText scores are classifier scores, not calibrated probabilities. No model weights are bundled or downloaded automatically.

The illustrative LID fixture is not validated benchmark data and no accuracy result is reported. Selective transliteration is opt-in and only considers tokens already labeled TELUGU_ROMANIZED. No verified offline engine is currently configured, bundled, initialized, or downloaded. Enabled runs without an injected verified engine report unavailable; the application does not check local assets. Engine exceptions or invalid candidates report failed, and ineligible tokens are marked skipped. Transliteration quality has not been experimentally evaluated. General Telugu-English contextual disambiguation, POS/NER, a real translation engine, and empirical evaluation remain unsupported beyond the narrow illustrative Phase 3 fixture. Phase 5 adds only an opt-in provider interface: without an injected real provider, requests are unavailable; the deterministic mock is test output, not translation. No translation-quality or semantic-preservation result has been measured. The provider seam is synchronous and has no explicit timeout or cancellation boundary; the default app has no external provider, so this is not an active provider failure. Before adding a potentially slow network provider, define bounded execution time, timeout behavior, cancellation/resource cleanup, and safe mapping of timeout errors to the public failure contract.


Phase 3 implements an explainable rule framework exercised by one illustrative English bank fixture. Its candidates and immediate English anchors test detection, selection, conflict abstention, provenance, offsets, and API integration; they do not establish validated Telugu-English linguistic behavior. UNKNOWN remains separate from ambiguity detection. Broader Telugu-English contextual disambiguation, rules supported by a reviewed Telugu resource, translation, and empirical semantic-preservation evaluation remain unsupported and require future work and evaluation.

## Phase 4 data limitations

The new annotation format, guidelines, CLI, and structural checks are implemented. The 16 examples are synthetic drafts; baseline token labels are suggestions, and no Romanized interpretation, Telugu equivalent, candidate meaning, or translation is asserted as verified. No human-reviewed dataset, evaluation split, measured Telugu-English disambiguation accuracy, or semantic-preservation improvement exists. Validator success checks format and internal consistency only; it cannot verify linguistic truth, source rights, or whether claimed human review occurred. Future work requires qualified annotation, provenance/licensing review, adjudication, and leakage-controlled evaluation.

## Phase 6B experiment limits

The paired direct/assisted orchestration is an in-memory framework, not an experiment result or evidence of improvement. The default assisted builder makes no linguistic substitutions because no validated Telugu-English replacement resource exists. Whitespace normalization is separately traced and is not meaningful linguistic assistance. Synthetic transformations exist only through explicit test injection and must not be treated as linguistic knowledge. The existing English `bank` ambiguity fixture and transliteration candidates are not replacement text.

Both arms call the same provider instance, but its current protocol accepts only text. English target and optional generation settings are requested metadata, not settings the provider is confirmed to have received. No real translation provider is configured; deterministic fake providers are test-only and are rejected by the evaluator. Phase 6D.2 provides local metric infrastructure, but there is no empirical evaluation result, persistence, human-reviewed benchmark, or measured quality/semantic-preservation result. Provider calls are synchronous without explicit timeout/cancellation/resource cleanup.

### Phase 6B.1 contract limits

The schema now rejects contradictory fallback and paired-arm records, but provenance metadata is not independently authenticated. Production linguistic substitutions remain disabled; strings labeled verified cannot enable them. Entity-review metadata is likewise not an entity detector. Synthetic edits are test-only, opt-in, and labeled synthetic. A future independently reviewed rule registry and entity-review process are required before production transformations.

The experiment supports direct_first (default) and assisted_first order and records attempted invocation order. Either deterministic order can still confound paired results for stateful, nondeterministic, or rate-limited providers; order and provider-state controls remain necessary before comparative interpretation. Requested English (en) and generation settings are not enforced by the current text-only interface. No empirical improvement is established. Synchronous provider calls still have no explicit timeout/cancellation boundary.

The experiment trace distinguishes intended arm text from actual provider input; unavailable or pre-invocation metadata failures do not claim a provider call occurred.

Phase 6D.1 defines the evaluation protocol and checks dataset readiness metadata. Phase 6D.2 adds a versioned in-project corpus BLEU/chrF implementation and report CLI. The readiness checker cannot authenticate reviewer identity, validate linguistic correctness or licensing, or automatically detect paraphrase/template leakage. The 16 synthetic draft records remain ineligible, and no real benchmark scores, human semantic scores, significance tests, or empirical improvement claims are available. The metrics are reference-based proxies and use a project-specific configuration; they are not interchangeable with other metric implementations. Human rating aggregation and real-provider evaluation remain future work. See [the evaluation protocol](evaluation_protocol.md).

Phase 6D.3 validates saved report structure and internal consistency under the supported Phase 6D.2 contract. **A VALID report establishes structural and internal consistency under the supported contract. It does not authenticate dataset provenance, independently verify original translation outputs, prove metric correctness without source artifacts, or establish semantic improvement.** The validator does not recompute corpus metrics, infer mock-provider use where the report lacks identity, authenticate provider IDs, or create research results.

Applying synthetic test transformations does not count as meaningful linguistic assistance or establish research efficacy. meaningful_assistance remains false until an independently reviewed production transformation mechanism is implemented.


### Phase 6C execution-order limits

Paired experiments can explicitly run direct_first (default) or assisted_first; the result records the actual attempted invocation order separately from stable arm identity. A provider call that raises is an attempt; a provider-ID failure before the call is not. Choosing a deterministic order improves traceability, not provider determinism or causal validity. Stateful behavior, rate limits, transient failures, and provider-side effects can still confound comparisons. No real provider, reviewed transformation resource, human-reviewed evaluation benchmark, or measured translation-quality/semantic-preservation improvement exists.
